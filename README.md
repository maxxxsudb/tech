# Tech AI Assistant

Текущая версия: **0.8.6**.

Компактный frontend-only app plugin для Grafana 13.0.2. Сборочные зависимости и отдельный backend-контейнер не нужны: ключ хранит Grafana в `secureJsonData`, запросы идут через штатный plugin proxy.

## Установка

Скопировать содержимое `plugin/` в каталог плагинов как `tech-ai-assistant-app` и добавить:

```ini
[plugins]
allow_loading_unsigned_plugins = tech-ai-assistant-app
```

Плагин автоматически учитывает `root_url`/`serve_from_sub_path` через `config.appSubUrl`.

Настройка: **Administration → Plugins and data → Plugins → Tech AI Assistant → Configuration**.

- `Шаблон провайдера`: заполняет поля для Ollama, LM Studio, vLLM, llama.cpp server, OpenAI, Gemini или Groq.
- `API URL`: адрес OpenAI-compatible сервиса так, как его видит сервер Grafana (например `http://ollama:11434`).
- `Chat completions path`: обычно `/v1/chat/completions`; `Models path`: обычно `/v1/models`. Можно указать любой свой путь. Итоговый адрес = API URL + путь, он показан под полями; если API URL уже заканчивается на `/v1`, повтор `/v1` из пути убирается при сохранении.
- `Model`: имя модели; кнопка **Загрузить список моделей** подставляет варианты из `/v1/models`.
- **Проверить подключение** отправляет короткий запрос с сохранёнными настройками и показывает ответ или понятную ошибку.
- `Окно контекста модели`: размер окна в токенах. Оценка начинается с 2 символов на токен и калибруется по `usage.prompt_tokens`, если сервер его возвращает (1,5–4 символа на токен, хранится в браузере для подключения). Плагин сжимает контекст и историю под этот лимит. Для Ollama задайте такое же значение через `OLLAMA_CONTEXT_LENGTH` или `num_ctx`, иначе Ollama молча отбросит начало промпта вместе с контекстом дашборда.
- `Как передавать контекст Grafana`: `Автоматически` использует system prompt и рассчитан на самые простые локальные модели. Расширенный режим добавляет именованный `grafana-context.json` к текущему user-сообщению, сохраняя чередование ролей. Это совместимый режим `chat/completions`, без загрузки файла в хранилище провайдера.
- `Потоковый вывод (stream)`: по умолчанию выключен для совместимости с простыми и кастомными моделями. После явного включения ответ появляется по мере генерации, есть кнопка **Стоп**. Если provider не поддерживает streaming, плагин автоматически повторяет запрос в обычном режиме и до конца сессии браузера больше не запрашивает stream у этой модели.
- `Как модель выполняет дополнительные запросы`: по умолчанию текстовый протокол, работающий с любой моделью без поддержки tools; можно включить native tools или native с откатом на текст.
- `Reasoning effort`: необязательный уровень рассуждения, например `low` для Gemini.
- `Max output tokens`: ограничение длины ответа; `0` использует значение провайдера.
- `API key`: хранится зашифрованным в Grafana. Для внутреннего сервиса ключ можно оставить пустым — Authorization header отправляться не будет.
- `Authorization header`: отключить для внутреннего сервиса без авторизации.
- `Передача снимков`: выбор JSON-схемы изображения и встроенная проверка уже сохранённого подключения. Кнопка **Проверить все форматы** создаёт тестовый JPEG с кодом `VISION-742`, отправляет пять коротких запросов и показывает ответ либо полный текст ошибки каждого формата. Успешный формат можно сразу выбрать и сохранить.
- Профили **Безопасный**, **Обычный** и **Глубокое расследование** меняют только поведение ассистента и лимиты, не затрагивая provider, модель, адрес и API key.

### Groq Free

Выберите `Provider: Groq Free`, сохраните отдельный Groq API key и модель `qwen/qwen3.8-27b`. Gemini/custom-профиль и его ключ при переключении сохраняются.

Контекст содержит текущий URL, UID и JSON дашборда (включая панели в свёрнутых rows), time range, текущие значения переменных и запросы панелей. На вкладке **Контекст** можно снять ненужные панели или выбрать **Только эта**; выбор сохраняется для дашборда до конца сессии браузера. Обычный вопрос, исправление и оптимизация datasource не вызывают. Для **Объяснить** можно настроить короткий пример фактических данных: по умолчанию до 3 строк/точек, 3 панелей, одного запроса на панель и за последний час. Если контекст не помещается в окно модели, сначала отбрасываются второстепенные поля, а под полем ввода видно, сколько токенов ушло, каким способом передан контекст и что было сжато.

Диалог хранится в `sessionStorage` отдельно для каждого дашборда и панели и переживает перезагрузку страницы; **Новый диалог** очищает его. Ответы рендерятся как Markdown, у блоков кода есть кнопки **Копировать** и **Открыть в Explore**, размышления reasoning-моделей (`<think>`) свёрнуты.

### Возможности 0.8.0

- В предпросмотре видна фактическая модель и можно выбрать **Только структура**, **Короткий пример** или настроить **Расследование**. Готовый JSON отделён от ещё не полученной выборки. В режиме структуры повторных запросов к datasource нет. Глобальные настройки лимитов не меняются.
- **Прикрепить файл**: PNG/JPEG и `.log/.txt/.json/.md`; изображения также можно вставить из буфера или перетащить. До отправки видны миниатюра, имя, размер и удаление. До 4 файлов, текст до 1 МБ, исходное изображение до 10 МБ. Изображения сжимаются в JPEG до 1600×1200 / 2 МБ. Текст включается в вопрос целиком: если не помещается в окно, выводится ошибка, файл не обрезается молча.
- **Изменить вопрос**, **Перегенерировать**, **Продолжить** работают от выбранного сообщения. При переотправке вопроса более поздние сообщения заменяются. Текстовые вложения сохраняются для уточнений; JPEG/base64 не сохраняются в истории. Для повторного анализа старого изображения его нужно прикрепить снова.
- В **Действия** доступны **Копировать диалог** и **Экспорт Markdown** с диапазоном, панелями и запросами. Экспорт не включает размышления модели и содержимое файлов.
- Предложенные запросы сравниваются построчно; можно отметить отдельные targets, проверить их в Explore, открыть редактор панели и применить после подтверждения. Неотмеченные targets сохраняются из актуальной версии дашборда.
- Сценарии **Почему нет данных?**, **Написать запрос**, **Сравнить периоды**, **Подготовить алерт**. Сравнение запрашивает два соседних периода одинаковой длительности только после подтверждения удвоенной нагрузки и общего таймаута. Алерт — только черновик, автоматически не сохраняется.

Вложения можно полностью отключить в Configuration (`Разрешить вложения файлов`): тогда в чате нет кнопки «Файл», а вставка и перетаскивание файлов не работают. Текстовые файлы (LOG, TXT, JSON, MD, CSV, YAML, XML, SQL, конфиги и любой другой небинарный файл) вставляются в сообщение текстом; двоичные (PDF, DOCX, архивы) отклоняются с подсказкой сохранить их как текст. У изображения в поле сообщения есть галка **в текст**: перед вопросом модель отдельным коротким запросом переписывает текст и содержимое картинки, и в основной запрос уходит только этот текст. Без галки изображение идёт в уже настроенную модель в выбранном `imageTransport`; автоматической проверки vision нет. Две отдельные text/vision модели запланированы на 0.9.0.

Преобразование картинки в текст **выключено по умолчанию для всех пользователей организации**. В Grafana откройте **Administration → Plugins and data → Plugins → Tech AI Assistant → Configuration**, найдите **«Разрешить преобразование изображений в текст для всех пользователей»**, измените галку и нажмите **«Сохранить»**. Затем закройте и снова откройте чат. Provisioning-параметр: `jsonData.imageToTextEnabled: false` (для включения — `true`). При выключении галка «в текст» скрыта и даже старые вложения/повторы отправляются изображениями, без отдельного запроса распознавания. Это не отключает обычные вложения и снимки.

Распознавание полезно для извлечения подписей и ошибок, но теряет визуальные детали и не обходит запрет API на base64: первый запрос всё равно содержит картинку. Оно использует общий `Max output tokens`, учитывается в суммарном usage; обрезанная расшифровка вызывает понятную ошибку вместо анализа неполного текста.

Окно ассистента разделено на вкладки **Чат**, **Контекст** (панели, снимок данных, скриншот, JSON того, что уйдёт в модель) и **Диагностика** (токены, время, последний отправленный контекст). Поле ввода видно на любой вкладке, быстрые действия находятся в компактном сворачиваемом блоке **Действия**. Перед отправкой прямо над полем ввода появляется блок «Проверьте и отправьте» с панелями, оценкой токенов и планом получения данных. Повторный Enter или повторный клик по тому же действию отправляет запрос. Настройка `Предпросмотр перед отправкой` позволяет показывать его всегда (по умолчанию), только когда собираются данные или скриншот, или не показывать. Ответ и обезличенную диагностику можно скопировать. Пользователь и организация добавляются в диагностику только отдельной галкой.

В 0.8.3 стартовый экран предлагает «Объяснить», «Найти проблему» и «Помочь с запросом». Компактная строка показывает выбранные панели, период и состав контекста; нажатие открывает его настройки. Ответы оформлены заголовками, списками, таблицами и блоками кода с копированием, в том числе при streaming. Во время запроса видны настоящий этап, счётчик полученных панелей и прошедшее время; «Остановить» прерывает запрос. Ошибки показывают короткое объяснение и повторную отправку, полный ответ API доступен по раскрытию. Длинные служебные тексты быстрых действий также свёрнуты, но не удалены из истории или запроса.

В 0.8.4 названия панелей в ответе стали ссылками: по клику дашборд прокручивается к панели и на пару секунд подсвечивает её. Ссылкой становится точное название панели или «панель N» с номером, который есть на дашборде; код и одинаковые названия не связываются. «Изменить вопрос» и действия под ответом стали тихими текстовыми кнопками, строка контекста больше не растягивается на всю ширину.

В 0.8.5 под ответом с данными панелей («Объяснить», «Расследовать» и уточнения по тому же снимку) находится свёрнутый блок **Данные к ответу**. Внутри — карточки с выбором ряда, максимумом/минимумом, последним значением и фактическим периодом с timezone. Пропуски не заменяются нулями и не соединяются линией. Показываются только ряды, чьи сводки действительно переданы модели, включая сжатие контекста; старые снимки без такой проверки явно помечены. Это исходные данные datasource без преобразований панели. График рисует браузер локально (до 60 точек), дополнительные запросы не выполняются и точки в модель не отправляются. Заголовок карточки показывает панель на дашборде. Выключается в Configuration: «Мини-графики под ответом».

В 0.8.6 карточки выбирают ряды после сжатия контекста: в каждой панели до трёх переданных модели рядов с наибольшим максимумом, поэтому блок не пропадает на панелях с многими рядами (`sum by (pod)`), а ряд с пиком всегда есть в выборе. Единица берётся из настроек панели (Prometheus и Loki не передают её в данных), время — в часовом поясе дашборда. В истории хранятся только показанные карточки; если sessionStorage переполнен, диалог сохраняется без графиков.

- На любом дашборде: оранжевая кнопка **AI** справа снизу открывает drawer поверх дашборда.
- В Command Palette (`Ctrl+K`): **Открыть Tech AI Assistant**.
- В Explore: **Add → Спросить AI**.
- Для контекста конкретной панели: `⋮` у панели → **Extensions** → **Спросить AI**.

В Configuration выбирается способ запуска: кнопка, Command Palette или оба. Там же задаются allowlist datasource UID, минимальная роль и лимиты данных панелей.

### Данные панелей

- Повторные запросы выполняются только для **Объяснить** с настроенным коротким примером или после подтверждения отдельного диалога **Расследовать**. Перед расследованием показаны фактический диапазон, число HTTP-запросов к datasource и число запросов панелей.
- Одновременно выполняется не больше 4 панелей. Общий таймаут расследования задаётся перед запуском, а во время сбора виден статус `Получаем данные: N из M`.
- Временной ряд передаётся сводкой за весь период: min, max, avg, first, last, время min и max и несколько последних точек (`последних точек`, 6). Серий на запрос не больше `максимум серий` (10): остаются серии с наибольшим max. Таблицы передаются колонками и строками, логи — самыми свежими строками (`максимум строк`, 20).
- Данные снимаются один раз на диалог: уточнения переиспользуют снимок, поэтому начало промпта не меняется и локальный сервер может не пересчитывать его. Снимок обновляется сам при смене панелей, диапазона времени или переменных, вручную — кнопкой **Обновить данные**.
- Если модель вернула ошибку, вопрос возвращается в поле ввода, есть кнопка **Повторить**, а вопрос без ответа не попадает в историю, которая уходит в модель.

Быстрые действия:

- объяснить, исправить или оптимизировать запрос;
- расследовать проблему после отдельного подтверждения диапазона, числа панелей, запросов на панель и общего таймаута. Там же отдельно разрешаются дополнительные read-only запросы модели к Loki, Prometheus и Tempo;
- показать diff предложенного `dashboard-json`, скопировать или применить его после подтверждения.

При применении плагин повторно загружает текущий дашборд, проверяет права, существование панели (в том числе внутри rows) и запрещает незапрошенную смену datasource. Сохранение идёт с проверкой версии: если дашборд успели изменить, правки не затираются. Токены, cookies и поля с секретами вычищаются из передаваемого контекста. Полный серверный аудит текстов запросов требует отдельного backend-компонента.

Для медленных и холодно стартующих локальных моделей задайте Grafana `GF_DATAPROXY_TIMEOUT=300`: стриминг показывает прогресс, но таймаут прокси всё равно действует. Перед демонстрацией прогрейте модель коротким запросом. Значение `Окно контекста модели` должно совпадать с `num_ctx`/`OLLAMA_CONTEXT_LENGTH`; безопасное значение по умолчанию — 8192.

«Минимальная роль» проверяется в браузере; маршруты plugin proxy доступны с ролью Viewer. Для жёсткого ограничения поднимите `reqRole` в `plugin.json`.

## Тесты

```bash
node --test test/*.test.js
```

Unit-тесты покрывают разбор стрима, текстовый протокол запросов, сжатие контекста, rows и санитизацию без Grafana и браузера. E2E-скрипты `test/verify-*.js` работают против запущенной Grafana.

Тесты запускаются **внутри единственного существующего контейнера Grafana 13.0.2**, без browser-test/PDF-образа: `powershell -File scripts/test-grafana.ps1`. Первый раз добавить `-Prepare`: устанавливаются системный Chromium, Node/npm и Puppeteer 24.24.1 без скачивания отдельного браузера. Зависимости сохраняются при `stop/start`; после удаления самого контейнера нужна повторная установка. Для проверок с реальными datasource должны работать существующие `tech-loki-1` и `mock-api`.

Интерфейс: четыре основных действия в сворачиваемом блоке, остальные в «Другие сценарии»; компактное прикрепление файла и растущее поле ввода. Черновик переживает закрытие панели. Прокрутка вверх во время ответа не сбрасывается; есть «К последнему сообщению». Панель шире и может разворачиваться на весь экран кнопкой в заголовке. Контекст и диагностика остаются отдельными вкладками, глобальные лимиты не меняются.

Сборка ZIP без Docker: `powershell -File scripts/package.ps1`. Архив содержит готовый плагин; распаковать его в каталог `tech-ai-assistant-app` и перезапустить Grafana. Скрипт проверяет совпадение версии и SHA-256 каждого файла после упаковки.

Качество модели и промпта проверяется набором эталонных вопросов: `node evals/run.js`, см. [evals/README.md](evals/README.md).

## Снимок дашборда

Снимок можно полностью отключить в Configuration (`Разрешить снимок дашборда`): тогда галки в чате нет и захват экрана не запускается. Если включён, в AI-панели отметьте `Сделать и отправить снимок дашборда для анализа`. Браузер попросит выбрать текущую вкладку Grafana, после чего плагин приложит один JPEG-кадр в выбранной JSON-схеме и сразу остановит захват. Галочка по умолчанию выключена. При ошибке UI показывает формат, разрешение, размер снимка и полный доступный текст ответа API; снимок автоматически не удаляется и запрос без него не повторяется.
