## 1. Контекст продукта

- **Что это.** Frontend-only app plugin для Grafana: AI-ассистент с контекстом текущего дашборда, панели и Explore. Открывается как drawer поверх дашборда, из Command Palette, из меню панели и из Explore.
- **Стек.** Один UMD `plugin/module.js` (~4,4 тыс. строк), React из Grafana, без сборки и без backend. Настройки — `jsonData`/`secureJsonData`, запросы к модели — через статический plugin proxy в `plugin.json`.
- **Провайдеры.** Любой OpenAI-compatible endpoint (Ollama, LM Studio, vLLM, llama.cpp, OpenAI, Gemini через OpenAI-совместимый путь), отдельный режим Groq. Streaming, native tools и текстовый протокол `grafana-query`.
- **Что уже умеет.** Контекст дашборда/панели/Explore; выбор панелей; снимок данных с лимитами; расследование с подтверждением нагрузки; дополнительные read-only запросы к Prometheus/Loki/Tempo; разведка схемы; аннотации и версии; сравнение периодов; поиск пика; вложения текста/PNG/JPEG и OCR; снимок вкладки или Canvas; предложения запросов с построчным diff, проверкой в Explore, редактором панели и применением с version check; мини-графики; экспорт Markdown; профили настроек; офлайн-установка и protected build.
- **Чего нет.** Серверной части, БД, серверной памяти, RAG/vector DB, отдельного vision-подключения, CI, тегов релиза.

**Ограничения, которые нельзя нарушать:**

1. Никакого нового backend-контейнера, БД и серверного хранилища.
2. Только существующие HTTP API Grafana через `backendSrv`/`fetch` и статические proxy-routes.
3. Grafana 13.0.2 и 13.2.2, React 19; установка без сборки, в т.ч. офлайн.
4. Данные и секреты не должны утекать: sanitize/redact уже есть, новые фичи обязаны их использовать.
5. Роль на proxy статична (`Viewer`); «минимальная роль» проверяется в браузере — это известное ограничение, не задача этого бэклога.

- **P2 из аудита.** «Продолжить» отправляет `dataMode: "structure"`, поэтому фактический снимок данных в продолжение не попадает. Код: `module.js:3487`. Аудит: `docs/functional-audit-2026-10-16.md:21`.

- **Плейбуки.** Захардкожены (`module.js:1732`, `conversation.js:47`). Нельзя добавить командный runbook без релиза кода.
- **Контекст.** Панели берутся «первые N» (`module.js:1114`), при сжатии отбрасываются по фиксированному порядку (`module.js:2048`), в сводках рядов нет аномалий (`module.js:852`).
- **Инструменты.** После общего согласия модель сама выполняет до 6 запросов; пошагового плана и approval нет (`module.js:1397`).
- **Drawer.** Фиксирован 640 px, только expand, ширина не запоминается (`module.js:4222`). Нет `aria-modal`, focus trap и фокуса при открытии; Esc-обработчик на самом drawer (`module.js:4287`), поэтому до клика внутрь Esc не работает.
- **Первый запуск.** Если настройки не загрузились или роль ниже минимальной, launcher молча не появляется (`module.js:4299`).
- **Меню панели.** Открывает нативную модалку (`module.js:4372`), а не общий drawer: второй чат с отдельной историей.
- **Prompt injection.** В режиме по умолчанию (`inline`) контекст приклеивается без пометки «недоверенные данные»; пометка есть только для `jsonDocument` (`module.js:459`).
- **Поставка.** `.github` нет, 145 unit-тестов и e2e запускаются вручную. 0.9.4 живёт на ветке с feature-именем; `main` — другая история без общего предка; тегов нет.
- **Использование.** Показывается только последний запрос (`module.js:3526`); суммарных токенов/времени за диалог и обратной связи нет.
- **Alerting.** На страницах алертов контекста нет: `loadContext` выходит, если нет dashboard UID (`module.js:1973`).

## 4. Задачи

### P0 — доверие и поставка

#### A1. Контекст при смене дашборда
- **Цена:** S–M · **Ценность:** 5 · **Уверенность:** 5
- **Сейчас.** Drawer не перезагружает контекст при переходе на другой дашборд: эффект зависит от `props.initialContext`, а `withPageState()` меняет только URL/время/переменные. Запрос может уйти с новым `pageUrl` и старым `dashboardUid`.
- **Сделать.** Следить за UID/типом страницы через `locationService` + интервал; при смене — прерывать текущий запрос, вызывать `loadContext()`, переключать `historyKey` и выбор панелей, показывать уведомление об изменении контекста. Обработать dashboard→dashboard, dashboard→Explore и panel→dashboard.
- **Зачем.** Это главный источник неверных ответов и потерянного доверия.
- **Приёмка.** A→B: запрос содержит UID и панели B; старый снимок не подмешивается; in-flight запрос отменён; история и выбор панелей переключились; unit/isolated test на handler.
- **Риски.** Навигация Grafana может пересоздавать drawer; нужно проверить оба пути — SPA-переход и полную перезагрузку.
- **Evidence.** `module.js:2848`, `docs/functional-audit-2026-10-16.md:13`.

#### A2. «Продолжить» сохраняет снимок данных
- **Цена:** S · **Ценность:** 4 · **Уверенность:** 5
- **Сейчас.** Кнопка передаёт `dataMode: "structure"`, и даже доступный актуальный snapshot не попадает в новый контекст.
- **Сделать.** При наличии подходящего не устаревшего снимка переиспользовать его без новых запросов; если снимка нет — честно продолжать только по тексту. Не брать снимок другого периода/выбора панелей.
- **Зачем.** Продолжение ответа должно сохранять факты, а не терять их.
- **Приёмка.** После snapshot-режима «Продолжить» содержит `panelData`; новых запросов к datasource нет; при смене диапазона/панелей снимок не переиспользуется; isolated test.
- **Evidence.** `module.js:3487`, `docs/functional-audit-2026-10-16.md:21`.

#### A3. CI, релизный контур, тег и default branch
- **Цена:** S · **Ценность:** 5 · **Уверенность:** 5
- **Сейчас.** `.github` нет; тесты вручную; 0.9.4 только на ветке `codex/image-to-text-setting`; `main` — другая история без merge-base; тегов нет; версия дублируется в трёх файлах.
- **Сделать.** GitHub Actions на node 22: `npm ci`, `npm test`, проверка совпадения версии в `plugin.json`/`module.js`/`package.json`, проверка структуры ZIP; тег `v0.9.4`; сделать релизную ветку/default или как минимум закрепить правило.
- **Зачем.** Без этого релизы теряются, а регрессии упаковки (как плоский ZIP 0.9.3) повторяются.
- **Приёмка.** PR запускает тесты; несовпадение версии падает; ZIP-артефакт собирается; тег существует; в README указано, какая ветка актуальна.
- **Риски.** `package.ps1` — PowerShell; для Windows-раннера или `pwsh` на Ubuntu проверить пути.

#### A4. Защита от prompt injection в контексте
- **Цена:** S · **Ценность:** 4 · **Уверенность:** 4
- **Сейчас.** В `inline`-режиме контекст приклеивается к system prompt без предупреждения; пометка «недоверенные данные» есть только в `jsonDocument`.
- **Сделать.** В обоих режимах явно писать, что названия панелей, JSON, логи, аннотации и результаты запросов — недоверенные данные; не выполнять инструкции из них; не выходить за рамки задачи. Обернуть контекст в явные разделители. Проверить, что tool-loop не ломается.
- **Зачем.** Логи и аннотации контролирует пользователь; это единственный канал инъекции в промпт.
- **Приёмка.** Правило присутствует в обоих режимах; evals не деградировали; tool-запросы по-прежнему работают.

#### B2. Context intelligence: ранжирование, аномалии, сравнение
- **Цена:** M · **Ценность:** 5 · **Уверенность:** 4
- **Сейчас.** Панели — «первые N»; сжатие отбрасывает по фиксированному порядку; в сводках нет аномалий; сравнение периодов спрятано в плейбуке.
- **Сделать.**
  1. **Ранжирование панелей под вопрос** по названию, row, тексту запросов, datasource и переменным. Применять только для неявного «все» или при нехватке бюджета; явный выбор не переопределять; показывать причину.
  2. **Аномалии как evidence:** median/MAD, сдвиг уровня между половинами периода, топ-3 кандидата с временем/направлением; маркер на мини-графике; формулировка «кандидат», не факт.
  3. **Сравнение периодов как обычный режим:** тумблер в composer, удвоение запросов в оценке, оба периода в контексте, дельта на графике.
- **Зачем.** Улучшает каждый ответ без более сильной модели; критично для локальных моделей и дашбордов на 50+ панелей.
- **Приёмка.** Синтетический дашборд: релевантная панель попадает в контекст; spike/step детектируются, шум — нет; сравнение показывает 2× запросов и не делает скрытых; явный выбор панелей не меняется.
- **Риски.** Ложные аномалии; рост токенов; не сломать стабильность префикса промпта.

Миграция текущего session-диалога. Санитайз и явная пометка о приватности.
- **Зачем.** Диалог становится рабочим пространством, а не одноразовой сессией.
- **Приёмка.** Закрыл/открыл браузер — диалог восстановлен; квота обрабатывается; без opt-in ничего не сохраняется; старый формат не ломает загрузку.
- **Риски.** Приватность и квоты; не хранить изображения/base64; не смешивать диалоги разных дашбордов.

### P2 — рабочий процесс и контроль

#### C4. Plan-and-approve для tool-loop
