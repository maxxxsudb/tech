# 0.9.13 — исправления самостоятельного аудита логики

- **Silence.** До POST фиксируется незавершённая попытка, после ответа — полученный silenceID. Неопределённый результат блокирует повторную запись и сохраняется в sessionStorage текущей организации. «Сверить результат» выполняет только GET: ищет известный ID либо единственное совпадение полей после потери ответа. Коррекция сервером прошедшего startsAt учитывается только при поиске кандидата; отличие не объявляется точным подтверждением. Фактический silence загружается для дальнейшего явного редактирования с тем же ID, preview/confirmation сброшены. При отсутствии или неоднозначности результата запись остаётся заблокированной; требуется проверка в Grafana. Ошибки 400/401/403/404/409/422 снимают pending, неопределённые сетевые/серверные ошибки сохраняют его. Автоматического повтора POST нет. Сохранение между перезагрузками зависит от доступности sessionStorage; это не серверная идемпотентность.
- **Enable.** Проверка поддержанного query → reduce → threshold отделена от планирования replay. Одиночный eval перед включением не зависит от попадания evaluation в минутный исторический отрезок и допускает SQL с текущим временем. Исторический replay сохраняет прежние ограничения времени, сетки и числа запросов. SQL guard, allowlist, свежесть proof, подтверждение возможных уведомлений и серверные проверки остаются.
- **Diff target.** Обычная правка одного текста запроса остаётся компактной. При изменении format/hide/datasource/других параметров показывается diff полного объединённого target, который будет сохранён, с прежним сворачиванием общих строк. Изменения дополнительных expression-полей также видны.
- **Ответ модели.** dashboard-json проверяется до отображения: targets должны содержать объекты, выражения/refId/datasource имеют ожидаемые типы, refId уникальны, число targets и длина выражений ограничены. null/массив/примитив в targets не ломает карточку. Некорректное предложение не получает действия применения; исходный текст остаётся доступен в сообщении.
- **История.** Dashboard/Explore chat, черновик и выбор панелей используют ключ с orgId. Alerting уже имел такую изоляцию. Старые ключи без организации не импортируются автоматически: достоверно определить их владельца нельзя. Эти старые записи не удаляются.

Новых постоянных разделов/сценариев нет; кнопка сверки появляется только при неопределённой записи silence. Изображения/OCR/MIME/transport, PostgreSQL-контейнер и backend не менялись. Предыдущие ZIP сохранены.
