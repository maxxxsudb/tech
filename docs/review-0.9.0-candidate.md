# Присланный 0.9.0: стратегия переноса

2026-10-14. Проверены пять файлов из Downloads. Они не установлены в плагин и не заменили рабочие файлы.

## Решение

База — наш текущий 0.8.8 поверх 0.8.7. Переносить полезные функции отдельно, с тестами. Не делать замену всего `module.js`: она возвращает уже исправленные UX-проблемы и добавляет скрытые запросы.

Сохраняем наш компактный composer, явные режимы данных, готовый снимок без перезапроса, согласие на изображение и его повторное использование после ошибки, ручную высоту ввода, группировку шагов, Configuration и предпросмотр по текущим настройкам. Лимиты панелей не меняем.

## Что взять

| Возможность | Решение |
| --- | --- |
| Explore и несохранённые изменения | Взять разбор Explore и реальные queries из контекста расширения. Не обещать живой JSON всего дашборда через несуществующий runtime API. Учитывать отдельные периоды разных Explore panes. |
| Прицельное расследование пика | Взять точный `peakAtMs`, действие «Проверить пик» и узкий период. Действие открывает наш диалог расследования, а не сразу запускает запросы. |
| Аннотации и изменения запросов между версиями | Взять чтение как опцию расследования с таймаутом/отменой и честным статусом. Запись аннотации — отдельный подтверждаемый черновик. |
| Разведка схемы | Взять как отдельный инструмент с разрешением пользователя, общим бюджетом и серверным ограничением периода/выборки. Сначала Prometheus/Loki; SQL — только после адаптации к datasource и диалекту. |
| Проверка предложенного запроса | Взять ручную кнопку проверки с выбранным периодом. Автопроверка — опция, по умолчанию выключена; учитывать бюджет и тип ошибки. |
| Canvas | Только дополнительный режим «Снимок выбранных графиков»: показывать, что попало и что пропущено. Не заменять снимок всей вкладки и не захватывать посторонние панели. |

Поиск панелей уже есть у нас. Горизонтальную ленту всех действий и постоянный ряд переключателей не переносить: это ухудшает компактность. Оставить второстепенные функции в раскрываемых настройках. `.traceql` можно добавить как небольшую отдельную доработку; остальная переработка `attachments.js` несущественна.

## Блокирующие дефекты кандидата

1. `runAssistant` вызывает `validateDashboardProposal` независимо от `options.queries`; `validateProposals=true` по умолчанию. Воспроизведено: при `queries=false` и ошибке доступа выполнены две проверки и два запроса модели. Проверки не списываются из `aiQueryMaxPerTurn`, проверяется до шести targets, период всегда последние 15 минут от текущего времени. Это не тест синтаксиса: выполняется настоящий datasource-запрос, в том числе для исторического дашборда. Самоисправление запускается и для ошибок доступа/сети, не только синтаксиса.
2. `executeSchemaTool` при неизвестном `datasourceUid` выбирает первый источник. Воспроизведён запрос к `correct` при аргументе `nonexistent`. Необходимо возвращать явную ошибку. Prometheus/Loki запрашивают весь список значений, фильтр и ограничение применяются только после получения; эти ветки не используют signal/общий таймаут. Один SQL с `LIMIT` не подходит всем заявленным источникам, в частности MSSQL.
3. `mergeLiveDashboardState` ищет `grafanaRuntime.getDashboardSrv`. На реальной Grafana 13.0.2 его значение — `undefined`. Ветка молча пропускается; правки могут подхватиться через конкретный extension context, но сбор всех несохранённых панелей не обеспечен. В случае ошибки определения Explore datasource тип необоснованно подменяется на Prometheus.
4. `snapshotKey` не учитывает изменённые targets/datasource и выбор событий. Воспроизведено совпадение ключей для двух разных запросов панели. При переносе живого состояния нужно инвалидировать данные по содержимому запроса; при выключении событий — не продолжать отправлять их из кеша. Это требование относится и к нашей базе перед добавлением живого состояния.
5. `capturePanelCanvasScreenshot` при отсутствии Canvas у выбранной таблицы переходит к общему поиску Canvas. Воспроизведён захват постороннего графика. Таблицы, логи, текст, HTML-легенды и подписи не попадают в Canvas-снимок. Canvas растягиваются до фиксированного размера и рисуются друг поверх друга, без их исходных координат. Нельзя называть результат точным снимком дашборда. Формат транспорта не изменился: этот режим не устраняет отказ модели от base64.
6. `parseAroundTimeRange` не ограничивает результат подтверждённым диапазоном. Воспроизведён период 2050 года при контексте 2026 года. Кнопка пика вызывает `send` с `queries=true` напрямую, минуя отдельное подтверждение параметров расследования. Exemplars из всех frames передаются каждому ряду: связь конкретного trace с конкретным пиком не доказана.
7. Загрузка аннотаций/версий включена по умолчанию и объединяется с панельными данными в `Promise.all`, но её запросы не отменяются общим signal и не ограничены общим таймаутом сбора. Ошибки молча превращаются в пустой результат. События читаются только при новом сборе panelData: переключатель не гарантирует их загрузку при структуре или готовом кеше.
8. `composerAllowQueries=true` по умолчанию разрешает дополнительные инструменты для обычного вопроса. Предпросмотр по умолчанию изменён с `always` на `data`. Переключатели разрешения запросов/событий не сбрасывают подготовленный preview action. Это меняет ожидаемую механику подтверждения.
9. В узкой панели подписи горизонтальной ленты действий налезают друг на друга. Появляются дополнительные постоянные строки управления; возвращены старое поле ввода и негруппированные настройки. Ручная высота ввода и безопасный повтор уже снятого изображения из нашей текущей реализации не перенесены.

## Проверки

- Синтаксис всех четырёх JS-файлов проходит `node --check`.
- Пять воспроизводимых регрессий: `node test/review-090-candidate.js <каталог-файлов>`. Сеть и datasource не используются; проверяются реальные функции кандидата с подменой внешних вызовов. Это проверки обнаруженных дефектов, не подтверждение готовности кандидата.
- Через подмену JS только тестовому браузеру сравнили наш текущий 0.8.8 и кандидат 0.9.0 на существующей Grafana 13.0.2. Файлы установленного плагина и настройки не заменялись. Модель и данные подменены; временный дашборд удалён. Новые контейнеры/образы не создавались, тестовая Grafana после проверки остановлена.
- При 1280×650: история 316 px у обоих; footer 138 px у нас и 145 px у кандидата. При 360×740: история 406/374 px, footer 138/177 px соответственно. Кандидат теряет 32 px истории (~8%). Наложение текста кнопок подтверждено снимком, хотя общая проверка horizontal overflow его не обнаруживает.
- Текущие 108 unit-тестов нашей базы проходят. Это не тесты новых функций кандидата. Его полный интеграционный прогон не выполнен; реальная модель заказчика не проверялась.
- В отдельном регрессионном прогоне нашей базы прошли 11 браузерных сценариев. Новый `verify-088.js` прошёл composer, поиск, изображения, размеры, Configuration и полную страницу, но завис на открытии нативного Extensions submenu. Это остаётся незавершённой проверкой модалки, а не успешным итогом всего прогона.

## Очерёдность

1. Explore + точное время пика; поправить ключ кеша перед добавлением живых запросов.
2. Чтение аннотаций/диффа по явной опции; затем подтверждаемая запись аннотации.
3. Разведка Prometheus/Loki и ручная проверка предложений, используя общий механизм разрешений/лимитов/прогресса.
4. Дополнительный Canvas-режим с отчётом покрытия. SQL-разведка и автоматическое самоисправление — после отдельных тестов совместимости и нагрузки.

Для автора кандидата: переносить ему наши UI-компоненты и инварианты отправки, а не наоборот весь его экран. Инструменты держать независимыми от оформления. Релиз 0.9.0 готовить только после адресных тестов перенесённых функций.

Официальные точки расширения: https://grafana.com/developers/plugin-tools/reference/ui-extensions-reference/extension-points . Поддержка Explore extension point сама по себе не подтверждает доступность живой модели дашборда.

## Результат переноса в нашу 0.9.0

Полезные функции реализованы в нашей базе, без замены экрана кандидатом. См. `release-0.9.0.md`: Explore, время пика/подтверждение, события/дифф, явный черновик аннотации, разрешаемая разведка Prometheus/Loki, ручная валидация и опциональный Canvas с покрытием. SQL-разведка, скрытое самоисправление и ненадёжная связь exemplars с рядами не включены. Регрессия нативной модалки устранена. Финальный прогон: 127 unit-тестов и 13 браузерных сценариев проходят.
