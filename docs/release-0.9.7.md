# 0.9.7 — черновик алерта, preview и rolling replay

Блок 4 из [плана](implementation-blocks.md). Существующее действие «Подготовить алерт» открывает форму внутри drawer вместо запроса модели. Основной чат и стартовый экран сохраняются. Изображения/OCR/транспорт не менялись.

## Черновик и создание

Builder строит новый query A → strict reduce B → threshold C из выбранного запроса панели. Поддержаны PostgreSQL, Prometheus и Loki; для SQL используется time_series. Порог задаётся явно, for и окно редактируются. Доступны last/mean/min/max/sum, gt/lt. NoDataState=NoData, execErrState=Error; keepFiringFor и сложные expressions в этом builder не поддерживаются. Переменные панели подставляет настоящий datasource; оставшиеся переменные не принимаются. Сырой API JSON от модели не исполняется.

Размещение — в существующей папке/группе. Группа читается перед тестом и созданием; её interval и состав сверяются с preview. Другие правила и interval группы не изменяются. Создание новой группы и изменение существующих правил остаются отдельным этапом. Выводятся labels/описание/runbook, JSON diff нового правила, маршрут и ограничения его проверки, число правил в группе.

«Проверить condition» выполняет один настоящий `/api/v1/eval`. Любое изменение черновика сбрасывает evidence. Создание доступно только Editor/Admin после отдельного подтверждения и свежих (до 10 минут) успешного preview и полного replay без NoData/Error для точного payload. Окончательные права проверяет API; 403 остаётся ошибкой. API всегда получает `isPaused: true`; включения нет. UID остаётся постоянным в рамках формы: повтор проверяет существующее совпадающее paused-правило и не создаёт дубль. Чужой/изменённый UID не перезаписывается.

Локальный журнал создания хранит requested/verified/failed-or-uncertain, пользователя/организацию, before=null и очищенный after. Журнал ограничен 50 записями/500 KB на org. Ошибка localStorage явно показывается после успешной записи и не провоцирует повторный POST. Страница Grafana остаётся источником фактического состояния; локальный журнал не является серверным аудитом. Предусмотрен экспорт JSON черновика с interval группы и сводкой replay.

## История и подбор

До запуска показывается план с числом eval/SQL-запросов, шагом, окном и бюджетом. На каждом шаге Grafana заново выполняет полный A → B → C с `now` этого шага и relativeTimeRange. SQL не выбирается один раз за весь период. Из reduce B берутся значения для сравнения threshold/for; согласованность исходного C проверяется с backend. Sweep до 5×5 вариантов не добавляет SQL-запросов. Перенос варианта меняет только форму и требует повторных проверок.

Поддерживаются периоды до 30 дней, до 500 шагов с настоящим interval выбранной группы и общим бюджетом 120 секунд (текущий запрос имеет собственный timeout). Шаг автоматически не укрупняется. Поэтому 7/14/30 дней при частой оценке могут быть отклонены ещё планом: нужно сократить период. Неполный прогон, ошибки и остановка не объявляются успешной проверкой и не разрешают создание.

SQL должен содержать движущееся окно через `$__timeFilter`/`$__unixEpochFilter` или пару `$__timeFrom`/`$__timeTo`. NOW/current_timestamp/current_date и другие значения текущего времени/случайности в replay отклоняются; сомнительные случаи тоже могут быть отклонены консервативно. SQL LIMIT не добавляется к alert-query, чтобы не менять условие; число возвращаемых строк не ограничивает стоимость сканирования БД. Повторяются выбранные SQL и его окно, не фактические исторические schema/data mutations.

Показываются наблюдаемые эпизоды, переходы, длительность, label sets, NoData/Error и покрытие. Unknown/исчезновение series разрывают непрерывность pending и остаются неизвестностью. Границы эпизодов на краях выборки помечены censored. Начальное состояние до периода неизвестно; принимается Normal на выбранной сетке. Это проверка условия и простой pending FSM, а не восстановление действительной истории scheduler, NoData/Error-алертов, retry/HA, inhibition, silence или доставки уведомлений.

В свёрнутых дополнительных полях доступны три PostgreSQL-шаблона: количество, среднее и процент ошибок по boolean-колонке. Имена объектов задаются явно и экранируются как identifiers. Шаблоны не угадывают таблицы, не обещают ноль при отсутствии данных и не выполняются автоматически.

## Проверки

Повторяемый non-prod прогон: `node test/verify-postgres-live.cjs`. Существующий PostgreSQL 16.15, временная БД/SELECT-only роль и Grafana 13.2.2. Fixture с точным временем пика проверяет отдельные rolling SQL evaluation, границы pending/firing/resolution и sweep. Созданные правила остаются paused и удаляются в finally. UI-отказ 403 симулируется; успешные SQL/eval/create API настоящие. Финальные результаты — в [плане блоков](implementation-blocks.md).

200/200 unit/isolated тестов на исходниках и обфусцированных модулях, 23/23 живых проверки и UI-регрессия 088/090/092/095 — PASS. Обычный/protected ZIP собраны, runtime зарегистрировал manifest 0.9.7. Все тестовые объекты удалены; бизнес-данные PostgreSQL не использовались. Protected UI отдельно в браузере не проверялся.
