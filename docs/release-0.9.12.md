# 0.9.12 — legacy datasource и исходный SQL в repair

- Строковый datasource UID панели/target и объект без type разрешаются через реестр Grafana в общую map `{uid,type}`. «Примерить», preview и apply используют один источник метаданных. Отсутствующий сервис/метод или недоступный реестр не ломают сбор контекста; неизвестный datasource не предлагается для примерки. SQL guard и allowlist сохраняются.
- Preview выполняет bounded SQL с LIMIT 101, но `validation.details.query` хранит исходный интерполированный SQL. Черновик «Исправить ошибку» получает его вместе с фактической ошибкой datasource. Служебная обёртка не переносится в предлагаемый запрос; пользовательский LIMIT сохраняется. Прежний контракт `details.query` с preview-обёрткой исправлен.
- Optional chaining учитывает отсутствие возвращённого datasource service. Preset существующего silence сохраняет заполненное время начала, а очищенное/невалидное восстанавливает текущим временем. Preview и подтверждение сбрасываются.

0.9.11 уже опубликована в ветке коммитами `14c0d92` и `ac93744`. Старые ZIP не заменяются. Изображения/OCR/MIME/transport, UI-сценарии и backend не менялись. Ограничение WITH RECURSIVE остаётся прежним.

Проверки и SHA-256 поставок: [протокол](implementation-blocks.md). Живые SQL-проверки используют существующий PostgreSQL, временную SELECT-only роль и изолированные fixture. В полном Assistant подменяется модель; SQL/eval/dashboard API настоящие. Protected UI получает точные production bytes; предварительные private-hook проверки используют source.
