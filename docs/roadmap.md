# Ближайший roadmap Tech AI Assistant

Дата фиксации: 2026-10-08. Базовая версия: 0.7.7.

## Текущее состояние

- UX/UI: 7/10.
- Возможности: 8/10.
- Сильная база: drawer поверх Grafana, вкладки «Чат / Контекст / Диагностика», Markdown, streaming/Stop/retry, выбор панелей, сбор фактических данных, расследование, предпросмотр, Explore, diff/apply и тест форматов изображений.
- Основной долг сейчас — не безопасность, а ясность контекста, удобство длинных диалогов, настройка подключения и работа с изображениями.

Принципы ближайших версий:

1. Сначала удобство и прозрачность, затем новые сценарии.
2. Не менять существующие лимиты данных без отдельного решения.
3. Сохранять frontend-only установку без отдельного backend-контейнера.
4. Старые настройки должны продолжать работать после обновления.

## 0.7.8 — UX и прозрачность, P0

### 1. Контекстная строка над полем ввода — M

Показать кликабельные chips:

- выбранные панели;
- диапазон времени;
- состояние данных и время снимка;
- наличие скриншота;
- используемая модель.

Явно разделять:

- `Передаём структуру: 4 панели`;
- `Получены данные: 3 из 4`;
- `Лимит действия «Объяснить»: 3 панели`.

Клик по chip открывает нужное место вкладки «Контекст».

### 2. Прокрутка и прогресс ответа — S–M

- Не прокручивать принудительно вниз при каждом чанке streaming, если пользователь читает ответ выше.
- Показывать кнопку «К последнему сообщению».
- Показывать этапы: `готовим контекст → получаем данные → анализируем изображение → ждём модель → выполняем datasource-запрос → формируем ответ`.
- Показывать прошедшее время и активную кнопку «Стоп».

### 3. Composer и обратная связь — S

- Автоматически увеличивать поле ввода до 4–6 строк.
- Хранить недописанный текст в `sessionStorage` по дашборду.
- После копирования показывать короткий toast «Скопировано» или ошибку clipboard.
- Сохранить Enter для отправки, Shift+Enter для новой строки; подсказку показывать рядом с полем.
- Состояние блока «Действия» запоминать в браузере.

### 4. Изменяемый drawer — S–M

- Drag-resize примерно от 420 до 900 px.
- Кнопки «На весь экран» и «Вернуть размер».
- Запоминать ширину в `localStorage`.
- На узкой ширине показывать diff вертикально, на широкой — в две колонки.

### 5. Выбор панелей — M

- Поиск по названию.
- Фильтры: выбранные, текущая, с запросами, по datasource/type.
- Группировка по row и selected-first.
- Компактные chips выбранных панелей.
- В ошибке «нужна одна панель» дать кнопку «Выбрать панель», а не только текст.

### 6. Configuration — M

Разделить длинную форму на:

1. Подключение.
2. Модели.
3. Контекст и данные.
4. Интерфейс.
5. Дополнительно.

Добавить sticky-блок `Сохранить / Сохранить и проверить`, индикатор несохранённых изменений, inline-валидацию URL/модели и тест значений из текущей формы до сохранения. Редкие transport/tool-настройки скрыть в «Дополнительно».

## 0.8.0 — Повседневные возможности, P1

### 1. Честный предпросмотр запроса — S

Раздельно показывать:

- что уже готово и точно уйдёт в модель;
- какие данные будут запрошены после подтверждения;
- сколько HTTP-запросов и панелей ожидается;
- какая модель будет вызвана.

### 2. Режим данных на конкретный запрос — M

В предпросмотре дать выбор:

- только структура;
- короткий пример;
- расследование с заданным диапазоном.

Это не меняет глобальные лимиты, а выбирает один из разрешённых режимов.

### 3. Вложения — M

- Paste/drag-and-drop/file для PNG/JPEG.
- Вложения `.log`, `.txt`, `.json`, `.md` как текстовый контекст.
- Thumbnail, размер, удаление до отправки.
- Системный `getDisplayMedia` оставить как вариант «Снимок экрана».

### 4. Действия над сообщением — S–M

- «Изменить и отправить заново».
- «Перегенерировать».
- «Продолжить ответ».
- «Копировать весь диалог» и экспорт Markdown с панелями, диапазоном и запросами.

### 5. Семантический diff запросов — M

- Сравнивать `expr/query/rawSql` построчно вместо полного JSON.
- Дать выбрать отдельные targets.
- Последовательность: `Проверить в Explore → открыть в редакторе панели → применить после подтверждения`.

### 6. Новые playbooks — M

- «Почему нет данных?».
- «Написать запрос».
- «Сравнить с предыдущим периодом».
- «Подготовить alert rule» без автоматического сохранения.

## 0.9.0 — Text + Vision, P1

Рекомендуемая схема — два последовательных этапа, а не два независимых ответа:

1. Vision-модель получает изображение и вопрос, возвращает короткие структурированные наблюдения/OCR.
2. Text-модель получает вопрос, visual evidence, JSON Grafana и данные панелей, затем выполняет основной ответ и обычный tool-loop.

Так сильная текстовая модель остаётся основной, а vision-модель используется только там, где нужна картинка.

### Этап A: две модели на одном endpoint/key — M

- Настройки `textModel` и необязательная `visionModel`.
- Режимы: `выключено / та же модель / отдельная модель этого подключения`.
- Если изображения нет — вызывается только text-модель.
- Если изображение есть — vision pre-pass без streaming/tools, затем text-модель.
- Visual evidence сохраняется в истории для уточнений; сырой JPEG в историю не сохраняется.
- В предпросмотре показывать цепочку `Vision model → Text model`.
- В диагностике учитывать latency/usage каждого этапа отдельно.

Старые настройки трактовать как «одна модель для текста и изображений».

### Этап B: отдельное vision-подключение — M–L

- `visionApiUrl`, `visionApiPath`, `visionAuthScheme`, `visionApiKey` в `secureJsonData`.
- Статические plugin-proxy routes `vision-chat` и `vision-chat-auth`; отдельный backend-контейнер не нужен.
- Раздельные кнопки проверки Text и Vision.
- Явная ошибка с действиями «Повторить vision» и «Продолжить без изображения»; без скрытого fallback.
- Ограничение размера изображения и адаптивное JPEG-сжатие перед отправкой.

Текущие пять image transport следует оставить в Advanced. Это варианты JSON для OpenAI-compatible Chat Completions, а не полноценные adapters Anthropic/Responses.

## Что пока не делать

- «Совет» из нескольких моделей и параллельные ответы.
- Автономное сохранение дашбордов или alert rules без подтверждения.
- RAG/vector DB и серверную долговременную память.
- Голосовой интерфейс.
- Большой одномоментный rewrite на TypeScript.
- Десятки provider adapters до появления реальной потребности.

## Минимальная матрица проверки

- Light/dark theme.
- 1366×768, 1280×650 и широкий drawer.
- Дашборд с 50+ панелями.
- Длинный streaming-ответ и ручная прокрутка вверх.
- Пустой API key.
- Text-only модель.
- Одна multimodal-модель.
- Раздельные Text/Vision модели.
- Ошибка vision и продолжение без снимка.
- Подпуть Grafana вроде `/crf/dashboard`.
