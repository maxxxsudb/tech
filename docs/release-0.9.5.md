# 0.9.5 — контекст, SQL и первый Alert Read

Реализованы блок 1 и первый читающий срез блока 2 из [implementation-blocks.md](implementation-blocks.md).

## Изменения

- Переходы между дашбордами, панелью, Explore и Alerting отменяют текущую работу и загружают контекст/историю новой страницы. Поздние результаты старой страницы отбрасываются.
- «Продолжить» использует подходящий актуальный снимок без новых запросов. При несовпадении периода/панелей продолжает по тексту, не обновляя данные автоматически.
- SQL-таблицы сохраняют формат, порядок, дробные числа, точность времени и типы полей Grafana. SQL time_series сохраняет полученные числовые значения в сводках. Округление не восстанавливает точность, уже потерянную datasource до получения JSON.
- Ручная проверка частичного target наследует настройки исходного запроса, как и применение.
- Общая инструкция для обоих способов доставки контекста отделяет данные от инструкций. Это снижение риска prompt injection, не серверная граница безопасности.
- Меню панели открывает общий drawer. Новый panel context заменяет контекст уже открытого drawer.
- Новый UMD/AMD-модуль `alerting.js`: только чтение правил, состояния и экземпляров через существующие API. На страницах Alerting доступны «Разобрать алерт»/«Сводка по алертам», группировка service/severity, ссылка на runbook, время снимка и ручное обновление.
- Правило без связанного дашборда получает контекст собственных datasource-запросов, включая PostgreSQL. Expressions остаются частью описания правила, но не исполняются как datasource-запросы.
- 403, недоступный API, неполное сопоставление экземпляров и обрезка списков видны отдельно. Ошибки не превращаются в утверждение «алертов нет».
- `jsonData.alertingEnabled` отключает чтение Alerting. По умолчанию включено; чтение происходит при открытии/смене контекста на Alerting, не в фоне на каждом дашборде.
- Версии и синтаксис проверяются `npm run check`; добавлен CI с тестами и проверенной ZIP-упаковкой. GitHub workflow подготовлен локально, удалённый прогон и публикация не выполнялись.

## Границы среза

Поддержан текущий snapshot Grafana-managed правил и экземпляров Grafana Alertmanager. Список ограничен 100 правилами и 50 экземплярами; сводные количества берутся из полного полученного ответа. Внешние Alertmanager/правила datasource, несохранённый редактор правила и история доставки не загружаются.

Структура связанной панели и повторная выборка данных за период инцидента не равны вычислению alert condition. Исторический replay, создание/включение/редактирование правил, silence, quality score, маршрутизация и сохранение кейсов остаются следующими блоками. Запись в Alerting отсутствует. Из Alerting нельзя применить dashboard-json или записать аннотацию в синтетическую панель.

SQL Explore, разведка PostgreSQL-схемы и дополнительные SQL tools ещё не включены. Получение данных существующих SQL targets работает через общий `/api/ds/query`; механизм ограничения количества строк в SQL не добавлялся.

Обработка и транспорт изображений/OCR не менялись. Минимальная версия Grafana остаётся 13.0.2.

## Проверки

См. итоговый протокол в [implementation-blocks.md](implementation-blocks.md). Живые проверки выполнены на Grafana 13.2.2 и существующем PostgreSQL 16.15: SQL-выборки, переменные, ошибки и разовое вычисление alert condition. Исторический replay и доставка уведомлений не проверялись. Отдельный прогон на минимальной Grafana 13.0.2 не выполнялся.
