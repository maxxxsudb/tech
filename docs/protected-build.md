# Защищённая локальная сборка

Исходники `plugin/` остаются читаемыми. Заказчику передаётся только `output/tech-ai-assistant-app-0.9.4-protected.zip`, не обычный ZIP и не репозиторий целиком.

**Перед поставкой:** 2026-10-16 проверено HEAD-запросом без авторизации, что исходный `plugin/module.js` в GitHub-ветке `codex/image-to-text-setting` доступен публично (HTTP 200). Пока доступ открыт, анализирующий может просто взять читаемую реализацию. Скрипт не меняет видимость репозитория и не удаляет ранее опубликованные исходники/ZIP; это отдельное решение владельца.

Ставьте защищённую сборку в чистую папку этого плагина. Распаковка поверх прежней версии может оставить старые читаемые attachments/conversation/query-tools.js — в новом ZIP их нет. Не удаляйте общий каталог plugins или данные Grafana. Уже переданные исходники ретроспективно не скрываются.

## Windows 10 / CMD

Нужен Node.js 22+ с npm и штатный Windows PowerShell. Из папки `ai-assistant`:

```bat
protect.cmd
```

Первый запуск выполняет `npm ci --ignore-scripts` с версиями из `package-lock.json`; для него нужен доступ к вашему npm registry либо заранее подготовленные зависимости. После установки зависимостей обычная сборка работает локально без сети. Код никуда не отправляется: применяется локальный API javascript-obfuscator, не облачный/Pro API.

Команда останавливается с ненулевым кодом при ошибке. Поставка публикуется из staging только после проверок. Каталоги `work/`, `test-results/` и `node_modules/` заказчику не передавать.

## Результат

`protected/tech-ai-assistant-app/` и защищённый ZIP содержат только:

```text
tech-ai-assistant-app/
  module.js
  plugin.json
  logo.svg
```

Папка plugin ID внутри ZIP сохранена: архив можно использовать со штатным установщиком Grafana. В отличие от исходного плагина, отдельные attachments/conversation/query-tools.js в поставке не нужны — их реализация включена в module.js.

## Преобразования

1. AST-объединение собственных AMD-модулей внутрь factory основного модуля. Внешние зависимости Grafana/React остаются внешними AMD-зависимостями.
2. Согласованное переименование только собственных helper-контрактов: объявления экспортов и статические обращения проверяются AST. При динамическом обращении, выходе helper-объекта из аудированного scope или новой структуре экспорта сборка прекращается. Глобальное переименование свойств не применяется.
3. Terser: локальные имена, удаление комментариев, безопасное сжатие, два прохода. `unsafe` выключен, свойства JSON/React/Grafana не переименовываются.
4. JavaScript Obfuscator: hexadecimal identifiers, control-flow flattening 0.2, string array 0.65 с RC4 и преобразованием обращений, перемешивание/смещение строк, дробление строк и числовые выражения. RC4 здесь дополнительный слой, не криптографическая граница.
5. AST-удаление `__test`, `__features`, `__context`, `__launcher` из финального экспорта. Grafana получает только `plugin`.
6. Синтаксические проверки, функциональные тесты, проверки контрактов и упаковка с SHA-256.

Не включены `renameProperties` для всего кода, `renameGlobals`, dead-code injection, self-defending, debug protection/таймеры, блокировка DevTools, скрытие console, привязка к домену и динамический eval. Эти опции заметно повышают риск поломки Grafana, CSP или производительности, а не только стоимость анализа.

Структурное усиление здесь — единый модуль, отсутствие осмысленного внутреннего ABI и приватных тестовых экспортов, потеря локальных имён и частичное разрушение control flow. Просто минификация или перекодировка строк этого не обеспечивают. Публичные ключи сетевого JSON, CSS/DOM-контракты и тексты интерфейса сохраняются по необходимости.

## Проверки

- Все unit-тесты запускаются на исходниках и затем на обфусцированных модулях. Временная версия для unit-тестов содержит private hooks; у release-main единственное последующее изменение — удаление этих экспортов AST-правкой. Тестовая версия не входит в поставку.
- Контракты release-main проверяются уже без hooks: внешний AMD-граф, регистрация страниц/компонентов/ссылок, единственный экспорт `plugin`.
- Проверяются синтаксис, отсутствие source maps и прямого eval/Function, отсутствие лишних файлов в поставке и неизменность SHA-256 исходников.
- Пять холодных VM-инициализаций дают медиану plain/protected. Защищённая инициализация должна уложиться в локальный бюджет `max(15 × plain, 500 мс)`. Это не обещание производительности на любом компьютере и не замер latency модели.
- Упаковщик проверяет структуру и SHA-256 каждого файла в ZIP. В защищённом ZIP даты записей фиксированы; одинаковые исходники, lock-файл, seed и toolchain дают повторяемые байты сборки.

## Браузерная проверка готового ZIP

`protect.cmd --grafana` дополнительно распаковывает staged ZIP и поднимает настоящую Grafana 13.2.2 с файлами из этого архива. Только после трёх UI-сценариев сборка публикуется в protected/output.

Нужны уже локальный образ `grafana/grafana:13.2.2`, Docker и установленный Edge (Windows) либо Chromium (Linux, можно указать `BROWSER_EXECUTABLE`). Скрипт не скачивает образы и отказывается запускаться, если Grafana уже работает. Временный контейнер удаляется в `finally`. Текущий fixture-стенд использует provisioning из соседней папки `dashboard-print`.

Сценарии: composer/режимы/поиск/повтор снимка/resize/настройки/нативная модалка; расследование/schema/events/Canvas/Explore; immutable sent context/черновик/мобильный popover. Код плагина и React настоящие; модель, данные и захват экрана в этих UI-тестах подменены. Это не тест реальной модели заказчика.

Изображения и `protection-report.json` лежат в `test-results/`, не в ZIP. Изменения исходного поведения двух дефектов из функционального аудита (навигация и «Продолжить») эта задача не исправляет: защита должна сохранять поведение, а не незаметно менять его.

## Ещё усилить с небольшим риском

Для отдельной поставки можно задать `--seed 12345` (при необходимости вместе с `--grafana`). Меняются раскладка имён/таблиц и результат преобразований, но все проверки выполняются заново. Seed — не секретный ключ. По умолчанию seed фиксирован, чтобы сборка была воспроизводимой.

Следующий эксперимент, а не включённая опция: локальная выборочная виртуализация одного-двух небольших алгоритмов планирования/сжатия контекста, без React/render/hot loops. Сначала те же корпусные тесты и отдельные CPU/latency-бюджеты. Облачная виртуализация не используется, полного непроверенного VM-слоя в поставке нет.

Гарантировать «неделю на восстановление» нельзя без отдельного независимого reverse-engineering испытания. Текущие проверки доказывают сохранение проверенного поведения и усложнение структуры, а не конкретный срок работы аналитика.

Инструменты: [Terser options](https://terser.org/docs/options/), [JavaScript Obfuscator](https://github.com/javascript-obfuscator/javascript-obfuscator). Версии зафиксированы в lock-файле.
