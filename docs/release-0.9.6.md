# 0.9.6 — PostgreSQL и аудит правил

Блок 3 из [плана](implementation-blocks.md). Новый backend не добавлялся. Изображения, OCR, MIME и транспорт не менялись.

## PostgreSQL

- Существующее разрешение «Разведка схемы» в расследовании теперь включает PostgreSQL. Метаданные получаются через datasource Grafana: tables, columns с numeric precision/scale, foreign_keys с правильным порядком составных ключей и indexes. Строки таблиц при разведке не читаются. Имена schema/table экранируются как литералы. До 100 элементов за шаг; при обрезке полное количество неизвестно.
- Дополнительные SQL-запросы работают в существующем подтверждённом расследовании и расходуют общий лимит запросов. Только один SELECT/читающий WITH; запрещены DML/DDL, несколько команд, recursive CTE, EXPLAIN и непроверенные функции. Это консервативный фильтр, не полный PostgreSQL-парсер и не серверная граница безопасности. Права datasource по-прежнему определяет PostgreSQL.
- SQL действительно оборачивается внешним LIMIT: по умолчанию 100, максимум 500 строк плюс служебная строка для определения обрезки. Служебная строка исключается из данных и статистики. При обрезке полного количества и пиков за пределами выборки мы не знаем. LIMIT ограничивает ответ, но не стоимость сканирования/агрегации; браузерный timeout не является серверным statement_timeout. Диапазон применяется SQL-макросами Grafana; литеральные условия времени не переписываются.
- SQLSTATE и подсказка по фактической ошибке возвращаются в существующий цикл инструментов. Для 42703/42P01 модель может уточнить схему и исправить SQL в пределах подтверждённого бюджета. После 42501 инструкция запрещает попытки обхода прав. Успешность исправления определяется повторным выполнением, а не обещанием модели.
- SQL-блок получает существующую ссылку «Открыть в Explore»: rawSql, table/code mode, выбранный datasource, диапазон и значения переменных, подставленные настоящим PostgreSQL datasource. При нескольких подходящих datasource ссылка не угадывает один из них.
- Новый default типов инструментов включает `grafana-postgresql-datasource`. Если ранее был явно сохранён ограниченный список в Configuration, он сохраняется; PostgreSQL нужно добавить в существующее поле типов. Allowlist UID и отключение schema discovery продолжают действовать.

## Аудит Alerting

В «Состав и свежесть данных» добавлено «Проверить качество правил». Чат, вкладки и основной сценарий сохранены. Аудит запускается по нажатию, читает API Grafana и не вызывает datasource. Отчёт прокручивается; есть поиск, фильтр уровня, экспорт JSON/Markdown и отправка первых 10 правил модели для объяснения с отметкой обрезки. Никаких изменений правил, contact points и policies.

Детерминированные проверки: for относительно evaluation interval, NoData/ExecErr → Normal, summary/description/runbook, team/service/severity, dashboard/panel link, paused/provenance, ошибки evaluation, окно запроса, переменные дашборда в SQL правила и дубли запросов/condition/labels. У каждого замечания есть evidence; предложение исправления — текстовый черновик. Checklist: 100 − 20 за error − 5 за warning, минимум 0; info не снижает оценку. Это эвристика, а не вероятность надёжности. Recording rules исключены из alert-checklist.

Читающая часть E9: дерево policies, вложенность, continue, наследование receiver/интервалов, обычные equality/negative и простые regex matchers, contact point, mute/active intervals с timezone и календарём. Используются статические labels правила и известное имя папки. Динамические labels запроса/шаблонов, сложные regex и неизвестные форматы помечаются partial. Ошибки доступа к правилам означают «аудит не выполнен»; недоступные дополнительные API видны отдельно. Настройки/адреса contact points в отчёт и модель не попадают.

Маршрут и временное подавление не доказывают доставку. История доставки, inhibition, silence и состояние внешнего Alertmanager этим аудитом не проверяются. Полный E9, создание/изменение правил и replay остаются следующими блоками. Использованы доступные на проверенной Grafana 13.2.2 legacy GET endpoints; их будущая миграция на `/apis` — отдельная совместимость.
