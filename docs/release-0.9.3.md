# 0.9.3 — открытие панели в Grafana 13.2.2 / React 19

2026-10-15.

## Исправлено

- Добавлен явный AMD-импорт `react-dom/client`, `createRoot` берётся из него. В React 19 старый `react-dom` больше не предоставляет методы монтирования.
- Удалено резервное открытие через приватное событие штатного sidebar: Grafana игнорировала наш ID из-за внутреннего allowlist.
- Командная палитра и Explore теперь открывают наш drawer, как плавающая кнопка. Меню отдельной панели сохраняет прежнюю штатную модалку.
- Повторное открытие не создаёт дубликат drawer; начальный контекст передаётся ассистенту. При синхронной ошибке монтирования пустая панель удаляется, пользователю показывается сообщение, ошибка записывается в Console.
- Сохранена совместимость со старым renderer для тестов и прежних окружений. Лимиты, контекст, модели и настройки передачи данных не менялись.

## Проверено

- 143/143 unit-теста, в стандартном изолированном режиме и с `--test-isolation=none`.
- Настоящая Grafana 13.2.2 с React 19: оранжевая AI открывает панель, отправляется вопрос через обычный предпросмотр, отображается ответ, работает закрытие/повторное открытие. На ширине 360 px кнопка закрытия остаётся в экране. Ошибок JavaScript нет.
- Тот же браузерный сценарий проходит на настоящей Grafana 13.0.2 с React 18, без ошибок JavaScript. Оба стенда используют один и тот же production-код, без подмены renderer. Только ответ LLM подменён тестовым.
- На Grafana 13.0.2 дополнительно проходят `verify-088.js`, `verify-090.js`, `verify-092.js`: composer/настройки/нативная модалка панели, расследование/инструменты/снимки, выбор панели/контекст/черновик/мобильная компоновка. Модель и данные в этих сценариях — заглушки.
- Проверка `test/diagnose-grafana-opening.js`: `GRAFANA_EXPECT_BROKEN=1` воспроизводит исходный сбой на старом коде; без этой переменной проверяет исправление. Для 13.0.2 задаётся `GRAFANA_EXPECT_VERSION=13.0.2`. Настройки теста восстанавливаются в `finally`.
