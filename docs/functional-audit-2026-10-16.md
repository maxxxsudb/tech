# Сохранность функционала — 2026-10-16

Проверен локальный рабочий вариант 0.9.4, включая ещё не закоммиченные исправления упаковки. Это аудит кода и изолированных обработчиков, не новый полный браузерный прогон и не проверка среды заказчика.

## Итог

Массового удаления рабочего функционала не обнаружено. С 0.7.7, 0.8.0, 0.8.7 и 0.9.0 ни одна именованная функция module.js не исчезла, старые ключи defaults сохранены без изменения значений. Само по себе это не доказывает отсутствие регрессий; дополнительно проверены основные UI-обработчики и цепочки отправки.

Сохранены выбор панелей, режимы данных, ограниченные примеры, снимок данных и обновление, расследование и native/text tools, работа без API key и без streaming, форматы изображений и их тестирование, вложения/OCR с общим запретом, редактирование/регенерация/продолжение, экспорт, proposals/diff/apply/Explore, мини-графики, разведка Prometheus/Loki, аннотации и версии.

## Важные функциональные провалы

### P1 — смена дашборда при открытом drawer

`loadContext()` вызывается эффектом, зависящим от `props.initialContext`, не от dashboard UID в URL. `withPageState()` обновляет pageUrl, время и переменные, но не получает модель другого дашборда. Наблюдение за URL не исправляет этот разрыв. Повторное `openDrawer()` при существующем drawer просто возвращается.

В изолированном настоящем обработчике отправки воспроизведено: после смены location на `/d/other/other` запрос содержит новую pageUrl, но старый `dashboardUid=tech`. Без браузерного воспроизведения нельзя утверждать, что любой способ навигации сохраняет drawer; однако код не гарантирует согласованность при его сохранении.

Нужно определять смену UID/типа страницы, отменять старый запрос, получать новый контекст и переключать историю по новому ключу. Не подмешивать старый снимок и данные в новый дашборд. Проверить A→B, dashboard→Explore и повторный вызов уже открытой панели.

### P2 — «Продолжить» теряет фактический контекст данных

Кнопка вызывает prepareSend с `dataMode: "structure"`. Из-за этого даже доступный актуальный snapshot не попадает в новый system context. Текст предыдущего ответа остаётся, но исходных panelData у модели нет.

Воспроизведено изолированным настоящим обработчиком: отправка в snapshot-режиме содержит panelData; нажатие «Продолжить» — уже нет. Дополнительных запросов к datasource при воспроизведении не выполнялось. Это поведение присутствует как минимум с первоначальной 0.8.0, то есть не регрессия последних 0.9.x.

Нужно переиспользовать относящийся к ответу актуальный снимок без повторного запроса; при его отсутствии честно продолжать только по тексту, не изображая наличие данных. Для старого ответа нельзя молча взять снимок другого периода/выбора панелей.

## Что не является потерянной ранее рабочей функцией

- Отдельные Text/Vision модели и подключения: остались в roadmap, реализации и настроек visionModel/visionApiUrl в текущем движке нет. OCR использует то же настроенное подключение.
- SQL-разведка, скрытый автопрогон новых targets и автоматическое самоисправление: намеренно не переносились из стороннего кандидата 0.9.0. Сохранены ручная проверка и согласие на нагрузку.
- Полное живое состояние несохранённого дашборда: сохранённый JSON плюс предоставленный extension context, не универсальное чтение всех правок редактора. Ограничение явно отражено в dashboardSource; не следует выдавать его за недавно сломанный функционал.
- Отсутствие повторного datasource-запроса при нажатии «Обновить со следующим вопросом»: намеренное отложенное обновление, а не неработающая кнопка.
- Изображения не сохраняются в sessionStorage: намеренное ограничение, для повторного анализа старого изображения требуется новое вложение/согласие.
- Панель отдельной панели Grafana всё ещё открывается нативной модалкой; остальные входы переведены на drawer. Это неоднородность интерфейса, не исчезновение анализа панели.

## Уже найденные и исправленные регрессии доставки

- 0.9.3: явный react-dom/client для React 19, устранение молча игнорируемого приватного sidebar event. Проверено ранее на Grafana 13.0.2 и 13.2.2.

- Последний коммит на момент аудита — c031312 (0.9.3). Исправления упаковки 0.9.4 и данный аудит пока не закоммичены/не запушены.

2. Сохранить данные при продолжении ответа, без роста нагрузки и подмены контекста.
3. Довести поставку 0.9.4, не смешивать её ZIP с плоским 0.9.3.
4. Затем возвращаться к двум моделям и общему живому состоянию редактора, как к новым возможностям, а не восстановлению удалённых.
