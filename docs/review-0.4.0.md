# Tech AI Assistant 0.4.0: что улучшить

Ветка `codex/custom-provider-assistant`, файл `plugin/module.js` (единый AMD-модуль, ~1080 строк).
Как проверял: прочитал код целиком и скриншоты из `test/*.png`. Живой стенд не запускал: твои
контейнеры работают на твоей машине, а в моём облачном окружении нет Docker и доступа к образам Grafana.
Всё, что помечено «гипотеза», стоит подтвердить на стенде.

## Коротко: топ‑3 по ценности

1. **Один чат вместо двух, с памятью и Markdown.** Главная точка входа (оранжевая кнопка AI) сейчас
   не помнит диалог, а ответы показываются сырым текстом.
2. **Стриминг ответа и кнопка «Стоп».** Для локальных моделей это разница между «ждёшь минуту
   перед пустым экраном» и «видишь, как пишет».
3. **Правильный и компактный контекст.** Переменные дашборда не подставляются в запросы, панели
   внутри rows теряются, а для локальных моделей с маленьким окном контекст молча обрезается.

Эти три пункта закрывают основной сценарий «открыл дашборд, спросил, уточнил, получил рабочий
запрос». Остальное ниже по убыванию ценности.

## P0. Чинить в первую очередь

### 1. Drawer не помнит диалог (баг в главной точке входа)
- `mountDrawerAssistant` отправляет только последнее сообщение:
  `callAssistant(..., [{ role: "user", content: ... }], ...)` (`plugin/module.js:902`).
  Уточняющий вопрос («а теперь то же для 5xx») модель получает без предыдущего ответа.
- React-компонент `Assistant` историю хранит (`module.js:562-565`), но drawer это отдельная
  реализация на голом DOM (`module.js:761-935`, ~180 строк), дублирующая UI.
- **Что сделать:** монтировать в drawer тот же `Assistant` через `react-dom` (Grafana отдаёт его как
  shared-модуль, достаточно добавить `"react-dom"` в `define([...])`). Удаляется ~180 строк дубля,
  все улучшения UI дальше делаются один раз. Историю держать в `sessionStorage` по ключу
  dashboardUid, чтобы закрытие drawer или перезагрузка после «Применить» не стирали чат.
- Плюс кнопка «Новый диалог».

### 2. Markdown и блоки кода
- Ответы выводятся как `textContent` / `pre-wrap` (`module.js:611`, `:828`). На скриншоте
  `test/investigation-success.png` видно `##`, `**`, таблицы с `|---|`: модель отвечает Markdown,
  а пользователь читает разметку.
- **Что сделать:** лёгкий рендер Markdown (Grafana уже содержит `renderMarkdown` в `@grafana/data`,
  он санитизирует HTML) и у каждого блока кода кнопки «Копировать» и «Открыть в Explore»
  (для PromQL/LogQL с datasource текущей панели). Это самое частое действие после ответа.

### 3. Стриминг, «Стоп» и размышления моделей
- Сейчас `stream: false` (`module.js:91`) через `getBackendSrv().post`, а README советует поднимать
  `GF_DATAPROXY_TIMEOUT=120`. На локальной модели 20–60 секунд пустого экрана с «…».
- Отменить запрос нельзя: нет `AbortController`.
- Reasoning-модели (Qwen3, DeepSeek-R1 и т.п. в Ollama/vLLM) кладут `<think>…</think>` прямо в
  `content`; плагин его никак не обрабатывает.
- **Что сделать:** `stream: true` и чтение SSE через нативный `fetch` к
  `/api/plugin-proxy/tech-ai-assistant-app/<route>` (backendSrv буферизует ответ). Кнопка «Стоп»
  через `AbortController`. `<think>` и `reasoning_content` сворачивать в «Размышления».
  Для режима с tools можно оставить non-stream на промежуточных шагах и стримить финальный ответ.
- *Гипотеза для проверки:* plugin proxy Grafana отдаёт `text/event-stream` без буферизации (Go
  ReverseProxy флашит такие ответы сразу). Проверяется одним `curl -N` к прокси на твоём стенде.
  Если таймаут dataproxy считается на весь ответ, а не до первого байта, `GF_DATAPROXY_TIMEOUT`
  всё равно понадобится, но пользователь хотя бы видит прогресс.

### 4. Контекст: переменные, rows, время
- Запросы панелей отправляются в `/api/ds/query` как есть, без подстановки переменных
  (`loadPanelData`, `module.js:227-234`; `getTemplateSrv` нигде не используется). На дашборде с
  `$job`, `$namespace`, `$__rate_interval` живые данные приходят ошибкой, и модель «чинит» то,
  что не сломано. Это бьёт по кнопкам «Исправить запрос» и «Расследовать».
- Переменные и время берутся только из URL (`module.js:498-508`): значения по умолчанию, не попавшие
  в URL, теряются. Нужно брать из `getTemplateSrv().getVariables()` и `getTemplateSrv().replace()`.
- Панели внутри строк (`type: "row"` с `panels: [...]` у свёрнутых rows) не видны: берётся только
  `dashboard.panels` верхнего уровня (`module.js:519`). То же в применении (`module.js:346`):
  «Панель N не найдена» для панели в свёрнутой row.
- Контекст строится из сохранённой версии дашборда (`/api/dashboards/uid`), несохранённые правки в
  редакторе модель не видит. Это стоит хотя бы показать в UI («анализируется сохранённая версия»).
- *Гипотеза:* для дашбордов в формате schema v2 (Grafana 12+/13, если включено) классический
  `/api/dashboards/uid/...` может не вернуть `panels` в ожидаемом виде. Проверить на стенде.

### 5. Бюджет контекста для локальных моделей
- В system prompt уходит весь JSON всех панелей вместе с `fieldConfig` и `transformations`
  (`summarizePanel`, `module.js:485-495`), плюс результаты запросов, затем строка режется
  `.slice(0, 120000)` (`module.js:95`). Обрезка рвёт JSON посередине, а 120 000 символов это
  порядка 30–40 тыс. токенов.
- Ollama по умолчанию работает с маленьким `num_ctx` и **молча отбрасывает начало промпта**, то есть
  как раз system prompt с контекстом. Модель отвечает «в общем», и непонятно почему.
- **Что сделать:**
  - настройка «Окно контекста модели, токенов» (по умолчанию 8k для локальных профилей);
  - компактный режим: для всех панелей только id/title/type/datasource/targets, полный JSON только
    для выбранной панели; урезание по бюджету по приоритетам (выбранная панель → данные → остальное),
    а не слайсом строки;
  - индикатор «~N токенов будет отправлено» над полем ввода и предупреждение при превышении;
  - в README: для Ollama задать `OLLAMA_CONTEXT_LENGTH` или `num_ctx` в Modelfile, иначе контекст
    теряется.

## P1. Удобство и функциональность

### 6. Профили провайдеров и «Проверить подключение»
- Сейчас два жёстких варианта: custom и Groq, Groq с отдельным маршрутом в `plugin.json`.
  Для «локальных и других нейросетей» не хватает пресетов: Ollama (`http://ollama:11434`,
  `/v1/chat/completions`, без auth), LM Studio, vLLM, llama.cpp server, OpenAI, Groq, OpenRouter.
  Пресет заполняет URL/путь/auth, остальное как сейчас.
- Кнопка **«Проверить подключение»**: короткий запрос и человеческая ошибка (DNS, 401, 404 пути,
  таймаут, модель не найдена). Сейчас ошибка конфигурации всплывает только в чате.
- Список моделей из `GET /v1/models` (есть у Ollama, LM Studio, vLLM, OpenAI, Groq) вместо ручного
  ввода; переключатель модели прямо в чате (быстрая/умная).
- Технически: маршруты в `plugin.json` статичны, но шаблонизируются из `jsonData`, поэтому можно
  завести 2–3 слота профилей (`profiles[0..2]`) с отдельными ключами в `secureJsonData`, без backend.
- В конфиге нет отметки, к какому провайдеру относится сохранённый ключ, и есть мелкие шероховатости:
  смена способа запуска требует перезагрузки и хранится в `localStorage` (`module.js:32`, `:680`).

### 7. Расследование надёжнее, особенно на локальных моделях
- Многие локальные модели или серверы не поддерживают `tools`, либо возвращают вызов текстом. Тогда
  «Расследовать» молча превращается в обычный ответ. Нужно: настройка «модель поддерживает tools»
  (авто-проверка при «Проверить подключение») и fallback-протокол «верни JSON-блок query».
- На последней итерации, если модель снова зовёт инструмент, выбрасывается ошибка
  (`module.js:301-321`): пользователь теряет всё собранное. Лучше на последнем шаге отправить
  `tool_choice: "none"` и получить итоговый ответ.
- Выполненные моделью запросы не видны пользователю. Показывать их карточками («запрос → N строк /
  ошибка», ссылка «Открыть в Explore»): это и доверие, и отладка.
- Режим расследования доступен только с кнопки. Сделать переключатель «Разрешить AI выполнять
  запросы» для свободных вопросов.
- Список типов захардкожен (loki/prometheus/tempo, `module.js:276`); как минимум стоит добавить
  Infinity и SQL-источники за отдельной галкой, раз на стенде они есть.

### 8. Безопасное применение изменений
- Сохранение идёт с `overwrite: true` (`module.js:355-360`): если кто-то сохранил дашборд между
  загрузкой и применением, его правки будут затёрты. Нужно передавать `version` из ответа и
  `overwrite: false`, а при конфликте показывать понятную ошибку.
- После применения `window.location.reload()` (`module.js:595`, `:864`) стирает чат. С историей в
  `sessionStorage` (п. 1) это решается, ещё лучше вариант «Открыть в редакторе панели» с уже
  подставленным запросом, без сохранения.
- Diff сейчас JSON против JSON. Для targets полезнее показывать построчный diff самих выражений
  `expr`.

## P2. Безопасность и инженерия

### 9. Ограничения проверяются только в браузере
- «Минимальная роль» и allowlist datasource проверяются в JS (`assertAllowedRole`, `module.js:133`),
  а маршруты прокси открыты для `reqRole: "Viewer"` (`plugin.json`). Любой Viewer может вызвать
  `/api/plugin-proxy/tech-ai-assistant-app/chat-auth` напрямую и тратить ключ или квоту.
  Если «минимальная роль» нужна всерьёз, `reqRole` в `plugin.json` нужно поднять до той же роли
  (он статичен) или уходить в backend-компонент.
- Хорошо, что есть санитизация секретов и вывод «Последний отправленный контекст». Не хватает
  предпросмотра **до** отправки, что особенно важно для внешних провайдеров (Groq/OpenAI):
  «будет отправлено: дашборд, 3 панели, 60 строк данных, снимок».

### 10. Сопровождаемость
- Нет исходников и сборки: 53 КБ рукописного AMD с `React.createElement`. Каждое изменение UI
  дорогое, тестов на чистые функции нет. Предлагаю `create-plugin` (TypeScript + webpack) или хотя
  бы вынести чистые функции (`sanitizeForAI`, `parseDashboardProposal`, `formatError`, построение
  контекста) и покрыть их `node --test` без браузера.
- e2e-скрипты захардкожены на `tech-ai-grafana-test:3000/crf/dashboard` и `/usr/bin/chromium`. Стоит
  вынести в `GRAFANA_URL` и добавить `package.json` со скриптом запуска.
- `provisioning/ai-assistant.yaml` пустой (`apps: []`): провижининг плагина с профилем Ollama
  ускорит развёртывание на новых стендах.

Что проверить на стенде, чтобы подтвердить гипотезы:
1. `curl -N` к plugin proxy с `"stream": true`: приходят ли чанки по мере генерации.
2. Дашборд с переменной в запросе панели: какую ошибку видит модель в `panelData`.
3. Панель внутри свёрнутой row: «Спросить AI» и «Применить».
4. Ollama с дашбордом на 15+ панелей: виден ли контекст модели (спросить «как называется дашборд?»).
