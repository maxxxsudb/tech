# 0.9.10 — SQL-предложения и удобство алертинга

## Корректность

- SQL-валидатор принимает скобки после BY, CASE, BETWEEN, LIKE, ILIKE и IS. Запреты записи, нескольких команд и непроверенных функций сохранены.
- Аудит проверяет переменные в rawSql и expr. Общая проверка используется в PromQL/LogQL builder; Grafana macros не считаются переменными. Строковый replacement в корректно разобранном label_replace исключён: `$name`/`${name}` могут обозначать именованные capture groups ([Prometheus](https://prometheus.io/docs/prometheus/2.55/querying/functions/#label_replace)). Это ограниченный анализ текста, не полный парсер PromQL/LogQL/Go templates.
- Для навигации и контекста используется один общий секундный poll и один history listener. Проверка templateSrv сохранена: переменные могут меняться без изменения URL. Периодические HTTP-загрузки не добавлены; watcher по-прежнему сравнивает идентичность страницы и отменяет устаревший запрос.

## SQL-сценарий

- Обычный SQL/PromQL/LogQL code block можно примерить к одной выбранной панели с единственным совместимым видимым target. Исходные refId, datasource, format и остальные настройки target сохраняются. Для Alerting/Explore, нескольких панелей/targets и несовместимых datasource кнопка недоступна. Само открытие diff ничего не исполняет и не сохраняет.
- Проверка запросов выполняется существующей явной кнопкой. При фактической ошибке datasource «Исправить ошибку» заполняет composer проверенным запросом, ошибкой и периодом. Модель вызывается только после отправки пользователем. Смена периода/переменных страницы сбрасывает результат проверки и подтверждение предложения; для code blocks и dashboard-json используется актуальный page context. Предлагаемое исправление проходит тот же diff/проверку/подтверждение.
- Неизменённые блоки длиннее четырёх строк сворачиваются с двумя строками контекста с каждой стороны. Раскрытие показывает все строки; изменения и полный JSON export не сокращаются. Общий renderer используется в proposal и incident diff.
- Нативный confirm заменён чекбоксом в карточке. После подтверждённой записи остаётся перезагрузка документа: простое обновление контекста ассистента не было принято за гарантированное обновление открытой Grafana-панели. Перед записью выбранные исходные targets и panel datasource сверяются с сервером. Конкурирующее изменение выбранного запроса блокирует запись, изменение невыбранного target сохраняется. Это дополнительная preflight-проверка; версия dashboard при POST остаётся серверной защитой от гонки после GET.

## Алёртинг и контекст

- `>=`/`<=` поддержаны в builder, replay/sweep, JSON import и изменении простого threshold. Сохраняются прежние требования preview/replay, paused creation, provenance и подтверждения записи. Равенство порогу проверяется на настоящем Grafana backend, а не заменой на «порог ± epsilon».
- Silence и начало инцидента используют datetime-local с подписью часового пояса браузера и переводом в UTC для API. Для silence доступны +1/+4/+24 часа; продление сохраняет исходное начало. Любая правка сбрасывает preview/подтверждение. Невозможное локальное время, включая весенний DST gap, не превращается молча в другой момент; повторяющийся осенний час разрешается стандартным правилом браузера.
- В существующем контекстном поповере флажки позволяют выбрать несколько панелей без закрытия. Название сохраняет прежнее действие «только эта панель». В режиме действия, требующего одну панель, остаётся одиночный выбор.

Изображения, OCR, MIME и транспорт не менялись. Основные четыре действия чата сохранены. Полный alert-builder без исходной панели, B2/E12/E13/C5 этим выпуском не добавляются.

## Проверки

Протокол и результаты приведены в [implementation-blocks.md](implementation-blocks.md). Живой SQL-прогон использует существующие PostgreSQL/Grafana, отдельные временные ресурсы и SELECT-only роль; бизнес-данные приложения не используются. В полном Assistant подменяется модель/настройки в браузере, SQL/eval/dashboard API настоящие. Тесты хранения кейсов и protected UI отдельно сохраняют свои указанные ограничения.
