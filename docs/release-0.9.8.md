# 0.9.8 — подтверждение запросов и управление Alerting

Блок 5 из [плана](implementation-blocks.md): C4, E8, E10, E14 в указанных ниже границах. Основные действия чата прежние. Управление, silence, импорт и журнал находятся внутри свёрнутого «Состав и свежесть данных» на странице Alerting. Изображения/OCR/транспорт не изменялись.

## План дополнительных запросов

В параметрах расследования можно включить «Подтверждать каждый план дополнительных запросов». Native tools и текстовые grafana-query/grafana-schema проходят один и тот же этап: аргументы, datasource, период, гипотеза и оставшийся бюджет показаны до исполнения. Пользователь отмечает шаги, пропускает план или останавливает расследование. По умолчанию ничего не отмечено. После подтверждения используются исходные аргументы; редактирование переданной callback копии не меняет запрос.

Без отметки запрос не исполняется. Пропущенные шаги видны модели и в истории. Abort прекращает ожидание и последующее выполнение. Общий лимит query/schema и число раундов сохранены. Опция относится к дополнительным запросам модели: начальная выборка по-прежнему отдельно задаётся и подтверждается в параметрах расследования. Стоимость SQL scan по числу строк не оценивается.

## Правила

Загрузка читает отдельный AlertRule и legacy provisioning metadata. Namespace берётся из runtime Grafana; `org-1` не угадывается. Прямые операции проверены на Grafana 13.2.2 и требуют соответствующего App Platform API. Нет fallback на перезапись всей группы.

Доступны title, for и порог простого threshold gt/lt, pause, enable, rollback и delete. Обновление и откат сохраняют правило на паузе. Остальные поля spec сохраняются. Изменение SQL, сложных expressions, labels и routing следует делать в Grafana или GitOps. Перед записью показываются spec до/после, текущие связанные экземпляры, несопоставленные экземпляры и ограничения влияния.

Любая непустая provenance, включая `api`, блокирует прямое управление. Это относится и к правилам, созданным provisioning API builder из 0.9.7. Заголовок обхода provenance не используется. Для таких правил доступны экспорт и GitOps-патч.

Перед PATCH правило перечитывается, сравниваются metadata/spec. Серверный JSON Patch дополнительно проверяет UID, resourceVersion и исходный spec. На стенде устаревший PATCH вернул 422. Обычные PUT и DELETE на этом стенде приняли устаревший resourceVersion: это **не** защита от гонки. Даже PATCH test не объявляется атомарной CAS хранилища. Для DELETE требуется ввод UID и отдельное принятие остающегося окна между чтением и удалением; DeleteOptions передаётся, но его соблюдение не предполагается. После записи состояние перечитывается; после удаления проверяется 404. Ошибка/abort после отправки записи требует сверки в Grafana, автоматического повтора нет.

Enable — отдельный шаг с успешным свежим eval точного spec и подтверждением возможных уведомлений. В первом срезе проверяется простая схема A → reduce B → threshold C; datasource/allowlist и SQL guard соблюдаются. Это текущий eval, не повторный исторический backtest и не проверка доставки. В живом тесте включалось только временное правило с заведомо ложным условием, затем сразу ставилось на паузу.

Rollback использует последнее подтверждённое before/after из локального журнала для этого UID. Если текущее содержимое отличается от after, откат отклоняется. Удаление не имеет локального undo. Журнал хранит requested/verified/failed-or-uncertain, актёра, before/after и ошибку, очищает чувствительные поля, ограничен 50 событиями/500 КБ на организацию. Потерянные/очищенные snapshots не восстанавливаются угадыванием. Это журнал браузера, не серверный аудит.

## Silence

Matchers предлагаются из labels экземпляра и редактируются. Поддержаны только непустые точные положительные совпадения; regex/отрицания существующих silence требуют Grafana. Комментарий обязателен, остаточный срок — до 7 дней. Preview читает настоящие текущие экземпляры, показывает совпавшие и предупреждает о будущих совпадениях. Silence подавляет уведомления, evaluation продолжается.

Перед POST заново проверяется состав совпадений; перед редактированием/завершением перечитывается сам silence. Изменившийся снимок требует повторного preview/загрузки. API не даёт атомарной версии: окно гонки остаётся. Создание и продление проверяют readback; завершение требует ID и подтверждения, использует singular `/silence/{id}`, проверяет expired. Список активных/предстоящих загружается явно. Contact points/policies не изменяются.

## Обмен

Экспорт JSON сохраняет Grafana-native правило; YAML — AlertRule resource или policy. GitOps — режим по умолчанию: выдаётся YAML с target и JSON Patch, включая проверки исходного состояния, без записи в API. DELETE в GitOps-патч не включается. Экспортированные данные нужно просмотреть перед добавлением в репозиторий.

Импорт JSON до 500 КБ поддерживает одно правило простой схемы A/B/C, включая экспорт builder/resource. Неизвестные настройки, которые изменились бы при пересборке, отклоняются. SQL проверяется. Импорт получает новый UID и открывает существующий builder: папку/группу выбирают заново, выполняют preview/replay и отдельное создание paused. Сложные правила и групповые provisioning-файлы остаются для GitOps; Prometheus-конвертера нет.

Проверяются реальные SQL/eval, PATCH и stale 422, rollback/pause/enable/delete, silence create/extend/expire, React UI подтверждения/импорта/silence и journal. Данные datasource/API не подменяются. Итоги, хеши и границы UI-проверки — в [плане](implementation-blocks.md).

API: [официальное описание Grafana](https://grafana.com/docs/grafana/latest/alerting/set-up/provision-alerting-resources/http-api-provisioning/). Поведение версии/preconditions выше установлено отдельными проверками именно локальной 13.2.2, а не выведено из названия resourceVersion.
